1. ТЕКУЩЕЕ СОСТОЯНИЕ ПРОЕКТА
======================================================================

Обязательная Spring Cloud-часть уже реализована на трёх доменных сервисах:

1. user-service         — пользователи, роли, регистрация, JWT;
2. car-service          — автомобили и карточки автомобилей;
3. test-drives-service  — записи на тест-драйвы.

Инфраструктурные приложения:

4. eureka-server        — Service Discovery, порт 8761;
5. config-server        — централизованная конфигурация, порт 8888;
6. api-gateway          — маршрутизация и Circuit Breaker, порт 8082.

Используется одна общая PostgreSQL-база.

Папка OLD PROJECT — исходный монолит. Она используется как источник моделей,
схемы базы и бизнес-логики, но не входит в основной порядок запуска.

Реализовано:

- JWT-фильтр;
- OpenAPI и Swagger UI;
- HTTP-логирование;
- rolling-файл логов;
- тесты контекста;
- тесты ролевого доступа.

API:

GET    /api/test-drives
GET    /api/test-drives/my
GET    /api/test-drives/{id}
GET    /api/test-drives/search?query=...
POST   /api/test-drives
PUT    /api/test-drives/{id}
DELETE /api/test-drives/{id}

Правила доступа:

- CUSTOMER создаёт тест-драйв;
- CUSTOMER видит только собственные записи;
- CUSTOMER не может получить чужую запись по ID;
- CUSTOMER не может изменить тест-драйв;
- CUSTOMER не может удалить тест-драйв;
- MANAGER может изменять тест-драйвы;
- ADMIN может изменять и удалять тест-драйвы;
- userId обычного пользователя берётся из JWT;
- userId нельзя подменить через JSON при создании;
- userId существующей записи нельзя заменить через PUT.

Swagger:

http://localhost:8087/swagger-ui/index.html

OpenAPI:

http://localhost:8087/v3/api-docs

Проверка:

cd .\test-drives-service
.\mvnw.cmd test
.\mvnw.cmd -DskipTests package

Ожидаемый результат:

6.4. Gateway

Маршруты:

[ ] /user-service/**
[ ] /car-service/**
[ ] /test-drive-service/**

Важно: login нельзя проверять открытием ссылки в браузере. Это POST-запрос:

POST http://localhost:8082/user-service/api/auth/login
Content-Type: application/json

{
  "username": "customer",
  "password": "<password>"
}

После login нужно передать полученный токен:

Authorization: Bearer <JWT>

Защищённый запрос без JWT должен вернуть 401 или 403 в зависимости от
конкретного уровня защиты. Ответ 405 на login означает, что был отправлен
GET вместо POST.

6.5. Circuit Breaker

Для проверки каждого маршрута:

1. запустить все сервисы;
2. выполнить обычный запрос;
3. остановить нужный доменный сервис;
4. повторить запрос через Gateway;
5. проверить HTTP 503 и JSON fallback;
6. снова запустить сервис;
7. проверить восстановление маршрута.

Минимально проверить test-drives-service:

http://localhost:8082/fallback/test-drive
